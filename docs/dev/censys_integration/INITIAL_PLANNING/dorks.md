Here are some sample patterns for SMB and FTP that mirror Dirracuda’s existing Shodan dorks. The first column shows the Shodan or legacy query; the second column provides a plausible CenQL translation using Censys’s v3 search syntax. The Censys query uses nested host.services:( … ) to ensure that all conditions apply to the same service, and fields like banner and software.product are used to match banner text and service metadata. For FTP, the Censys ftp model exposes a status_code field that contains the numeric FTP response (e.g., 230 for successful login).

Purpose	Shodan/legacy query (Dirracuda defaults)	CenQL translation
FTP – Anonymous login / open directory	port:21 "230 Login successful" – Dirracuda’s FTP module uses this as the base query for anonymous‑login FTP servers.	host.services:(protocol=FTP and port=21 and banner:"230 Login successful") – matches FTP services on port 21 whose banner contains the text 230 Login successful. Alternatively, to target the protocol field directly, you could use host.services.ftp.status_code=230 to find services that respond with the 230 status code.
FTP – Anonymous login with specific file type	Example Shodan dork: port:21 "230 Login" "backup" (look for servers that allow anonymous login and expose a backup file).	host.services:(protocol=FTP and port=21 and banner:"230 Login" and banner:"backup") – ensures the FTP banner contains both 230 Login and backup, indicating an anonymous‑login server with backup files exposed.
FTP – FTPS/TLS capability	There isn’t a standard Shodan dork, but searching for "Auth TLS" in the banner often reveals FTPS.	host.services:(protocol=FTP and port=21 and banner:"Auth TLS") – finds FTP services that advertise TLS (implicit or explicit) in the banner. You can narrow it further using host.services.ftp.auth_tls_response:234 to match servers that reply with 234 (“AUTH command ok”).
SMB – Authentication disabled (Samba)	smb authentication: disabled product:"Samba" – used by Dirracuda to find Samba servers permitting guest connections.	host.services:(protocol=SMB and port=445 and banner:"authentication disabled" and software.product:"Samba") – searches for SMB services on port 445 whose banner indicates authentication is disabled and whose software product is Samba. If the banner text isn’t reliable, you can start more broadly with tags:smb and software.product:"Samba" and then filter down.
SMB – SMBv1 enabled	Shodan dorks often look for hosts exposing the obsolete SMBv1 protocol (e.g., port:445 os:windows "smbv1").	host.services:(protocol=SMB and port=445 and smb.smbv1_support=true) – matches hosts where Censys has parsed the SMB negotiation and determined that SMB v1 is supported (true indicates the host responded positively to an SMBv1 session request).
SMB – Open shares / guest access strings	Example Shodan pattern: port:445 "NT_STATUS_ACCESS_DENIED" to find servers exposing guest access or misconfigured shares.	host.services:(protocol=SMB and port=445 and banner:"NT_STATUS_ACCESS_DENIED") – looks for SMB banners containing the status message NT_STATUS_ACCESS_DENIED, which often appears when shares are probed without credentials. You could also search for banner:"share" or banner:"anonymous access" to find common misconfigurations.

These examples are starting points. You can combine additional conditions such as country filters (and location.country_code=US) or time filters (host.services.scan_time:[now-72h TO *]) to control data freshness. Also remember that Censys queries consume credits; limit the page_size and result pages according to your free‑tier budget.

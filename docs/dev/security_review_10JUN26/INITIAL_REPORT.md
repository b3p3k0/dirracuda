Catalogued eight security vulnerabilities spanning HTTP redirects, path traversal, and decompression bombs

Reviewed the development branch (~164k LOC Python). I focused on the threat model that matters here: you connect to attacker-controlled SMB/FTP/HTTP hosts and pull their data onto disk. I traced the download/extract write paths, the SQL layer, the subprocess boundary, the web UI auth, and secret handling. Ran the test suite where deps allowed (678 shared + 38 webui auth tests pass; the only failures were from impacket missing in my sandbox, not real bugs).

Overall this is well above the typical solo/AI codebase. The things below are what I'd fix, ranked.
Findings

1. HTTP browser/verifier follow redirects silently → SSRF (medium) shared/http_browser.py:257,336 and commands/http/verifier.py:112 use urllib.request.urlopen, whose default opener auto-follows 3xx. Combined with check_hostname=False + CERT_NONE (http_browser.py:154-155), a malicious open-dir server can 302 a list/download/verify request to an internal address (e.g. 169.254.169.254, RFC1918) or a different port. This breaks the README's "verification stays locked to the exact endpoint" guarantee — the lock only applies to the initial URL, not the redirect target. The VM/VPN guidance limits blast radius but doesn't eliminate it. Fix: build a custom opener with a redirect handler that rejects cross-authority/cross-scheme redirects (or disables them for downloads).

2. SMB bulk extract joins an unsanitized server-supplied share name into the local path (medium) gui/utils/extract_runner.py:393: dest_path = download_dir / share / file_info["local_rel_path"]. local_rel_path is correctly sanitized via _safe_parts (strips ./..), but share is used raw. A malicious server (custom impacket responder) can advertise a share name containing / or .., escaping the quarantine root → arbitrary write. Real SMB servers can't name shares that way, but you don't control the server. Fix: run share through _safe_parts/_sanitize_label before the join, same as you already do for local_rel_path and in quarantine.py.

3. Image-viewer decompression-bomb guard runs after decode (low/medium) gui/components/image_viewer_window.py:99-102: Image.open() then img.load() (full decode into RAM) then the w*h > max_pixels check. The check never protects you — OOM happens during load(). Pillow's built-in DecompressionBombError gives partial cover (~2×89M px), but your own limit is dead. Fix: check img.size after open() and raise before calling load().

4. ZIP import has no decompression-bomb / size cap (low/medium) gui/utils/data_import_engine.py:308: zipf.extractall(temp_dir) with no bound on total uncompressed size or member count. Zip-slip via .. is actually mitigated by CPython's extractall (it strips ../absolute paths), so this is a disk-exhaustion DoS, not arbitrary write. Fix: sum zi.file_size for zi in zipf.infolist() and cap count before extracting.

5. ~456 silent except … : pass blocks (systemic, maintainability) This is the classic AI-codebase smell and the most likely source of "deeply flawed in ways I can't see." Several sit on security-relevant operations that fail silently: the exec-bit strip (smb_browser.py chmod & 0o666 in a bare except: pass), quarantine event logging, partial-file cleanup. A swallowed failure here means a downloaded file silently keeps its exec bit, or cleanup silently doesn't happen. Fix: at minimum logger.debug(..., exc_info=True) in catch-alls so failures are observable; reserve true pass for cases where you've reasoned that failure is genuinely irrelevant.

6. FTP RETR is CRLF-injectable via server-supplied filename (low) shared/ftp_browser.py:394: f"RETR {remote_path}". A directory entry whose name contains \r\n injects FTP commands — but back to the same attacker-controlled server, so impact is near-nil. Still, reject control characters in remote_path before issuing the command (defense-in-depth, and it prevents client-side confusion).

7. Latent: SMBNavigator.download_file(preserve_structure=False) is broken on POSIX (low) shared/smb_browser.py:216: Path(norm_path).name where norm_path uses backslashes. On Linux pathlib doesn't treat \ as a separator, so .name returns the entire path string as the "filename." Currently harmless because every live caller passes preserve_structure=True and bulk extract bypasses this method — but it's a landmine for the next caller. Fix: ntpath.basename / PureWindowsPath(norm_path).name.

8. TLS verification off by default (informational) allow_insecure_tls=True default is defensible for auditing sketchy hosts, but it means MITM of your audit traffic is undetectable. Worth a documented toggle rather than a silent default.
